# Repo map

A quick map of where things live, so you can go straight to the right file.
Path aliases (from `tsconfig*.json`):

| Alias | Resolves to | Use from |
| --- | --- | --- |
| `@server/*` | `server/*` | anywhere (server and UI, for shared types) |
| `@app/*`, `@/*` | `src/*` | UI |
| `@test/*`, `@cli/*` | `test/*`, `cli/*` | tests, CLI |
| `#private/*` | `server/private/*` | **only** inside `server/private/` |
| `#dynamic/*` | `server/private/*` (enterprise/saas) or `server/*` (oss) | outside `server/private/` when you need the private implementation on paid builds |
| `#open/*`, `#closed/*` | `server/*`, `server/private/*` | internal to the esbuild `#dynamic` switcher; don't use |

## Top level

```
server/          Express API server (TypeScript, bundled with esbuild.mjs)
src/             Next.js dashboard (App Router)
messages/        i18n JSON. Only en-US.json is edited by hand; Crowdin generates the others
config/          config.yml (+ privateConfig.yml on enterprise), example configs
cli/             pangctl CLI
install/         installer (Go)
docs/            Developer docs for agents and contributors (this folder)
test/            Shared test helpers
scripts/         Build/test scripts (run-tests.mjs)
esbuild.mjs      Server bundler; holds the #private guard and the #dynamic switcher
drizzle.*.ts     Drizzle configs (drizzle.config.ts is generated by set:pg / set:sqlite)
```

Generated and gitignored, switched by npm scripts: `server/build.ts`
(`npm run set:oss|enterprise|saas`), `tsconfig.json` (copied from
`tsconfig.{oss,enterprise,saas}.json`), `server/db/index.ts`, `drizzle.config.ts`,
`server/setup/migrations.ts` (`npm run set:sqlite|pg`).

### Entity routers (`server/routers/<entity>/`)
Each folder has `index.ts` (re-exports), one file per operation
(`createX.ts`, `getX.ts`, `listXs.ts`, `updateX.ts`, `deleteX.ts`), and often
`types.ts` / `validation.ts`. See `docs/crud-endpoints.md`.

Main ones: `org`, `site`, `resource` (public resources), `siteResource` (private
resources), `target` (public resource targets), `policy` (resource policies),
`client`, `user`, `role`, `domain`, `idp`, `apiKeys`, `accessToken`,
`blueprints`, `labels`, `redirect`, `aiProvider`, `aiBudget`, `virtualApiKey`,
`auditLogs`, `certificates`.

### Fetching data
- **Server components / layouts**: `internal.get<AxiosResponse<T>>(path, await authCookieHeader())`, with `internal` from `@app/lib/api` and `authCookieHeader` from `@app/lib/api/cookies`. Use `getCachedOrg` / `getCachedOrgUser` from `@app/lib/api/*` for the org.
- **Client components**: `const api = createApiClient(useEnvContext());`, then `api.get/put/post/delete`. Errors go to `toast({ variant: "destructive", description: formatAxiosError(e, t("...")) })`.
- Response types are imported straight from the server router, e.g. `import { GetResourceResponse } from "@server/routers/resource"`.
